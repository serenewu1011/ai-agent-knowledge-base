## 這篇在說什麼

這篇記錄 LINE 會議助理的主要元件，以及目前能確認的開發經驗。這是個人專案紀錄，不代表所有功能或正式環境狀態都已完成。

## 核心概念

系統可以拆成幾個責任不同的部分：

| 元件 | 在專案中的用途 |
|---|---|
| LINE Messaging API | 接收使用者訊息，並提供 LINE 內的互動入口。 |
| LIFF | 在 LINE 中開啟網頁表單，處理補充資訊或使用者操作。 |
| Cloudflare Workers | 提供後端 API 與系統流程處理。 |
| Cloudflare D1 | 儲存會議、時段、參與者等結構化資料。 |

LLM 可以協助理解自然語言，但實際執行仍要由後端依照明確規則處理。模型供應者、使用中的模型名稱與正式部署狀態，需以最新專案設定和測試紀錄確認。

## 會議助理中的例子

目前的開發紀錄可以確認，系統已做出建立會議、查看會議或投票相關資訊，以及主持人管理介面等功能；部分流程曾在測試環境操作。每個功能的部署狀態可能不同，新增紀錄時要註明「已測試」或「規劃中」，不要只用「已完成」概括。

既有架構也包含 LINE 身分驗證、LIFF 表單、Cloudflare Worker 與 D1。V4 為隔離測試系統，涉及正式 LINE Webhook 的說明應先查最新設定。

## 開發注意事項

- 使用者介面負責收集輸入；後端負責驗證、權限檢查與實際資料操作。
- 資料庫欄位或 API 行為有變動時，應同步更新相關文件。
- 記錄功能狀態時，附上測試日期與測試環境，避免把測試環境誤寫成正式環境。
- 不將金鑰、使用者識別碼或可直接存取系統的連結放入公開知識庫。
